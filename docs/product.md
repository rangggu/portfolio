# Product

## 컨셉

반복되는 일은 AI에게 맡기고, 사람의 눈과 판단이 필요한 문제(1px 어긋남·깜빡임·버벅임·이상한 동작, 그리고 구조를 어떻게 나눌지)는 먼저 찾아 풀어낸다.

## 닉네임

사이트 로고와 JSON-LD `alternateName`에 **Myu**를 사용합니다.

## 첫 화면 문구

아래 문구를 그대로 사용합니다.

> 김규리 · 프론트엔드 개발자
>
> 마지막 1px까지 봅니다.
> 반복되는 일은 AI에게 맡기고, 사람의 눈과 판단이 필요한 문제는 먼저 찾아 풀어냅니다.

## 캔버스 구조

피그마 작업 화면을 모티브로 한 캔버스 위에 프레임을 배치합니다. 피그마 UI를 그대로 재현하지 않고, 점 무늬 캔버스·프레임 이름표·현재 프레임의 선택 테두리 정도만 차용합니다.

### 프레임 배치

```
  ┌──────────┐
  │ 첫 화면  │
  │  /       │
  └──────────┘
       │
  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
  │ 소개     │──│ 경력     │──│ 프로젝트 │──│ 기술     │──│ 학력·자격│
  │ /about   │  │ /career  │  │/projects │  │ /skills  │  │/education│
  └──────────┘  └──────────┘  └──────────┘  └──────────┘  └──────────┘
                                                               │
                                                          ┌──────────┐
                                                          │ 연락처   │
                                                          │ /contact │
                                                          └──────────┘
```

### 프레임별 라우트

| 프레임    | 경로         | title                          |
| --------- | ------------ | ------------------------------ |
| 첫 화면   | `/`          | 김규리 \| 프론트엔드 개발자    |
| 소개      | `/about`     | 소개 \| 김규리 포트폴리오      |
| 경력      | `/career`    | 경력 \| 김규리 포트폴리오      |
| 프로젝트  | `/projects`  | 프로젝트 \| 김규리 포트폴리오  |
| 기술      | `/skills`    | 기술 \| 김규리 포트폴리오      |
| 학력·자격 | `/education` | 학력·자격 \| 김규리 포트폴리오 |
| 연락처    | `/contact`   | 연락처 \| 김규리 포트폴리오    |

직접 접근하면 해당 프레임에서 시작합니다.

## 이동

이동 방식은 화면 폭이 아니라 **입력 방식**으로 결정합니다.

### 마우스·트랙패드 (pointer: fine) — 카메라 이동

오른쪽 위 버튼으로 **읽기 모드**(기본)와 **자유 모드**를 바꿉니다. 고른 모드는 기억해 다음 방문에도 그 모드로 시작합니다.

#### 읽기 모드

사용자는 아래로만 스크롤합니다. 카메라가 프레임 사이를 이동하는 것은 스크롤 위치에 연동된 연출입니다.

- 첫 화면 → 소개: 아래로 이동
- 소개 → 경력 → 프로젝트 → 기술 → 학력·자격: 카메라가 오른쪽으로 (가로 스크롤을 흉내 내는 연출)
- 학력·자격 → 연락처: 아래로 이동
- 프레임 사이에서는 멈추지 않습니다. 프레임 경계를 넘는 스크롤이 들어오면 곧장 **다음 프레임 맨 위**(아래로) · **이전 프레임의 끝**(위로)으로 미끄러져 갑니다. 화면에 다 들어오는 프레임은 스크롤 한 번이면 바로 다음 프레임입니다.
- 긴 프레임: 카메라가 아래로 따라 내려가고, 끝 근처(화면 절반 이하 남음)에 오면 프레임 끝 안내를 보입니다. 끝에 닿은 뒤에도 화면 높이의 30%만큼 더 내릴 수 있어(프레임이 계속 올라가며 아래 캔버스가 드러남) 끝에 닿자마자 넘어가지 않고, 그걸 넘는 스크롤이면 바로 다음 프레임으로 갑니다. 위로도 같아서 맨 위에 닿은 뒤 그만큼 더 올려야 이전 프레임으로 갑니다.
- 넘어간 뒤 남은 휠 동작(트랙패드 관성)은 버려서 두 칸씩 넘어가지 않습니다. 한 화면씩 넘기는 키(Space·Page)는 아직 못 본 내용이 남았으면 먼저 그 프레임 끝까지만 보여 줍니다.
- 옆 프레임·메뉴·뒤로 가기로 **바로 옆 프레임**에 갈 때는 카메라가 곧장 미끄러져 가고, **먼 프레임**은 짧게 페이드한 뒤 바로 옮깁니다. 미끄러지는 동안(0.4~0.6초)은 휠·스크롤 키를 무시합니다.
- 확대(Ctrl·Cmd+휠, 핀치)·좌우 이동(Shift+휠)·전체 보기(Shift+1·0)를 하려 하면 화면 확대 대신 모드 버튼 아래 말풍선(「확대하거나 자유롭게 둘러보고 싶으신가요? [자유 모드로]」, 6초)으로 자유 모드를 권합니다. 꼬리가 모드 버튼을 가리켜 버튼 위치도 알려 줍니다.

#### 자유 모드

피그마처럼 캔버스를 자유롭게 둘러봅니다. 프레임 안의 글자 선택·링크는 그대로 동작합니다.

| 조작                                         | 동작                                  |
| -------------------------------------------- | ------------------------------------- |
| 휠·트랙패드                                  | 상하좌우 이동                         |
| Shift+휠                                     | 좌우 이동                             |
| Ctrl·Cmd+휠, 트랙패드 핀치                   | 마우스 위치 중심 확대·축소 (10%~200%) |
| 빈 캔버스 끌기, Space+끌기, 가운데 버튼 끌기 | 이동                                  |
| 방향키                                       | 이동                                  |
| Shift+1 / Shift+0                            | 전체 보기 / 100%                      |

- 화면 가운데에 있는 프레임이 현재 프레임입니다 (메뉴 바·주소가 따라 바뀜).
- 메뉴·뒤로 가기는 그 프레임을 100%로 맞춰 날아갑니다. 프레임을 눌러도 이동하지 않습니다.
- 오른쪽 아래에 「− 비율 + · 전체 보기」 버튼이 있습니다. 비율을 누르면 100%가 됩니다.
- 모드를 바꾸면 보던 곳에서 이어집니다 (읽기 → 자유는 그 자리 그대로, 자유 → 읽기는 보던 프레임의 처음부터).

### 터치 (pointer: coarse) — 좌우 스와이프

프레임 안에서는 세로 스크롤, 프레임 사이는 좌우 스와이프로 이동합니다. 옆 프레임 가장자리(12px)와 간격(12px)이 보여서 넘길 수 있다는 힌트 역할을 합니다.

### 폴더블 기기

폴더블은 접힘·펼침 모두 터치(pointer: coarse)이므로 항상 스와이프 방식입니다. 접힘 ↔ 펼침으로 뷰포트가 바뀌어도 이동 방식이 전환되지 않습니다.

## 옆 프레임

현재 프레임 좌우로 이웃 프레임이 살짝 보이고, 누르면 해당 프레임으로 이동합니다. 긴 프레임을 따라 내려가면 옆 프레임은 위로 지나가고 빈 캔버스가 보이는 게 정상입니다.

## 프레임 끝 안내

상시 이동 버튼은 두지 않습니다. 프레임 끝이 보이면 "계속 스크롤하면 03 프로젝트 →" 같은 안내를 표시합니다 (화면에 다 들어오는 프레임은 도착하면 바로, 긴 프레임은 끝까지 화면 절반 이하가 남았을 때부터, 넘어가는 동안은 숨김). 안내는 메뉴 바 바로 위의 말풍선이고, 꼬리가 다음 프레임의 메뉴 항목을 가리킵니다.

## 뒤로 가기 기록

- 스크롤로 프레임이 바뀌면: 주소만 교체 (`replaceState`, 기록 안 남김)
- 메뉴를 눌러 이동하면: 기록 추가 (`pushState`)

## 구현 원칙

### 스크롤은 진짜, 카메라 이동은 연출

실제 문서는 프레임 순서대로 이어지는 일반 페이지이고, 화면의 카메라 이동만 스크롤 위치에 연동된 효과로 처리합니다. 아래가 정상 동작해야 합니다:

- 키보드 탐색 (Tab, 화살표, 스페이스)
- 스크린리더 (프레임 순서대로 읽힘)
- 페이지 내 검색 (Ctrl+F)

### prefers-reduced-motion

움직임 줄이기를 켜도 같은 화면(PC는 캔버스, 터치는 스와이프)을 보입니다. 스크롤·스와이프처럼 사용자가 직접 움직이는 것은 그대로 두고, 이동·확대 같은 연출만 애니메이션 없이 바로 바꿉니다.

### 뷰포트 변경 시 유지

접힘 ↔ 펼침, 가로 ↔ 세로 전환 시 현재 프레임과 스크롤 위치가 유지되어야 합니다.

## 이력서 데이터

첫 화면, 소개, 경력 타임라인, 기술·학력 프레임, Person JSON-LD, 인쇄 이력서가 `content/resume/`의 데이터 하나를 같이 씁니다.

- 형식은 TS입니다 (`profile`, `intro`, `timeline`, `skills`, `education`·`certifications`). 타입은 `src/lib/resume/types.ts`에 있습니다.
- 형식이 틀리면 빌드가 실패합니다 (기간 `YYYY-MM`과 순서, id 중복, URL·이메일 형식, 기술 분류, 프로젝트 글의 `timelineId`).
- 아직 모르는 값은 지어내지 않고 `TODO`로 둡니다. `TODO`는 형식 검사를 건너뛰고 화면·JSON-LD·평문에서 빠집니다.
- 진행 중이면 `period.end`를 생략합니다.
- 성과 요약(`achievements`)은 회사 레인에만 씁니다 (타입으로 막음).
- 경력 항목과 프로젝트 글의 연결은 글 frontmatter의 `timelineId` 하나가 기준입니다. 한 항목에 여러 글이 연결될 수 있고, 초안 글은 프로덕션에서 링크 없이 표시됩니다.
- 기술 분류는 고정 목록입니다: 언어·프레임워크 / UI·스타일링 / 데이터·상태 / 테스트·품질 / 빌드·배포 / 분석 / 협업 / AI. 기술은 분류와 이름만 둡니다 (처음 쓴 시점·숙련도는 싣지 않음, 어디서 어떻게 썼는지는 경력·프로젝트 글이 보여 줌).

## 경력 섹션: 두 갈래 타임라인

| 레인               | 시각      | 내용                   |
| ------------------ | --------- | ---------------------- |
| 회사 (주)          | 굵은 막대 | 성과 요약              |
| 사이드·개인 (보조) | 얇은 선   | 이름, 한 줄 설명, 링크 |

- 부트캠프 시기 작업은 옅게 표시합니다.
- 케이스 스터디가 있는 항목만 모달로 열립니다.
- 학력·자격은 타임라인에 넣지 않고 별도 프레임에 둡니다.
- 사이드 레인의 마지막 항목은 이 포트폴리오입니다.
- 넓은 프레임(안쪽 폭 768px 이상)에서는 두 레인이 나란히. 좁은 프레임에서는 한 레인으로 접히고 상단에 레인 라벨이 표시됩니다.

## 여백 메모

본문의 특정 텍스트에 연결된 짧은 메모로, "왜 그렇게 했는지"를 적습니다. 연결된 텍스트는 점선 밑줄 등으로 표시합니다.

- 메모는 말풍선 아이콘이 달린 카드입니다. 평소에는 회색으로 본문보다 물러나 있고, 강조되면 포인트색이 됩니다 (피그마 어노테이션 모티브).
- 넓은 프레임(컨테이너 832px 이상): 메모를 본문 오른쪽에 항상 표시합니다. 메모나 연결 텍스트에 hover/focus 시 서로 강조되고, 그동안만 연결 텍스트 줄과 메모가 선으로 이어집니다.
- 좁은 프레임(832px 미만): 메모는 숨김 상태이고, 연결 텍스트를 누르면 해당 문단 바로 아래에 펼쳐집니다.

## 프로젝트 글 구조

모든 프로젝트 글(케이스 스터디)은 같은 형식입니다. 깊이는 글 길이로 자연스럽게 차이가 납니다.

권장 구성 (빌드에서 검사하지 않음):

1. 소개
2. 역할·기술
3. 주요 성과
4. 문제와 해결 — **"처음 떠오른 방법 / 한 번 더 들여다본 뒤"** 이야기를 여기서 풉니다.
5. 회고 — **"아직 남은 것"**을 여기서 풉니다.

- 원문은 `content/projects/{slug}.mdx`입니다. frontmatter: `title`, `summary`, `period`(`{ start, end }`, 진행 중이면 `end` 생략, `YYYY-MM`), `tags`, `thumbnail`(`/projects/{slug}/` 아래), `timelineId`(경력 타임라인 항목 id), `draft`(선택, 기본값 `false`).
- **초안:** `draft: true`인 글은 개발 서버(`yarn dev`)에서만 보이고 글 상단에 "초안" 표시가 붙습니다. 프로덕션 빌드에서는 페이지, 프로젝트 목록, sitemap 모두에서 빠집니다. 공개하려면 `draft`를 지우거나 `false`로 바꿉니다. 빌드할 때 `SHOW_DRAFTS=true`를 주면 초안을 포함하는데, Lighthouse CI 측정 전용이며 배포 빌드에서는 쓰지 않습니다.
- **캔버스에서 열기:** 캔버스 안의 글 링크는 캔버스를 떠나지 않고 그 위에 모달로 엽니다. 화면 폭 768px 이상은 가운데 모달, 미만은 아래 시트입니다. 주소는 `/projects/{slug}`로 바뀌어 공유·새로고침하면 단독 페이지가 열립니다. 제목 바에 글 제목과 「새 페이지로 열기」가 있고, 닫으면(Esc·바깥 누르기·닫기·뒤로 가기) 보던 프레임과 위치로 돌아옵니다.
- 여백 메모는 글 안에서도 `MarginNoteGroup`·`MarginNoteAnchor`·`MarginNote`로 씁니다. 비교 블록 컴포넌트는 글을 쓰다가 필요해지면 추가합니다.

## 인쇄

캔버스를 그대로 찍지 않고, 종이용으로 따로 설계한 **A4 이력서**가 찍힙니다 (`features/resume`의 `ResumeDocument`).

- 캔버스 페이지는 어느 프레임 주소에서 인쇄해도(Cmd+P, 오른쪽 위 더보기의 「이력서 인쇄」) 캔버스 대신 이 이력서가 찍힙니다 (`PrintResume`, 화면에는 없음). 케이스 스터디 모달이 열려 있으면 그 글이 찍힙니다.
- 미리보기: `/resume` (개발 서버에서만. 배포 사이트에서는 404이고 링크·sitemap에 없으며 noindex).
- 데이터는 캔버스와 같은 `content/resume`과 프로젝트 글입니다. 비어 있는(TODO) 값·항목은 싣지 않습니다.
- 구성: 머리(이름·직함, 한 줄 소개, 연락처 칩: 이메일·GitHub·포트폴리오 주소) → 소개(콜아웃) → 경력(회사 경력만, 최근 순: 역할·기간·성과 목록·관련 프로젝트 칩) → 프로젝트(2열 카드: 기간·요약·태그·글 주소) → 기술(분류별 칩) → 학력·자격.
- 섹션 이름은 왼쪽 좁은 열(포인트색), 내용은 오른쪽. 배경·칩 색은 인쇄에서도 빠지지 않게 색 출력을 강제합니다 (`print-color-adjust: exact`). 색은 테마와 상관없이 늘 라이트이고, 글자는 루트 13px 기준입니다.
- 경력 항목·프로젝트 카드·기술 줄은 쪽에서 잘리지 않습니다.
- **부록:** 이력서 뒤에 프로젝트 글 전체(케이스 스터디)를 프로젝트 순서대로 붙입니다. 글마다 새 쪽에서 「부록 N · 프로젝트」와 글 주소로 시작하고, 이력서의 프로젝트 카드에 부록 번호를 적습니다. 종이·PDF만 받는 사람도 글을 다 볼 수 있게 하기 위해서입니다.
- 케이스 스터디 글: 단독 페이지든 캔버스 위 모달이든 글만 인쇄됩니다 (모달 제목이 글 제목, 버튼 제외). 여백 메모는 문단 아래에 펼치고, 코드 블록은 쪽에서 잘리지 않으며 긴 줄은 접습니다. 외부 링크는 뒤에 주소를 붙입니다.
