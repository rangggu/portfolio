# Product

## 컨셉

작은 불편을 그냥 지나치지 않고, 화면의 디테일부터 그 뒤의 구조까지 한 번 더 들여다본다.

## 닉네임

사이트 로고와 JSON-LD `alternateName`에 **Myu**를 사용합니다.

## 첫 화면 문구

아래 문구를 그대로 사용합니다.

> 김규리 · 프론트엔드 개발자
>
> 작은 불편을 그냥 지나치지 않습니다.

## 캔버스 구조

피그마 작업 화면을 모티브로 한 캔버스 위에 프레임을 배치합니다. 피그마 UI를 그대로 재현하지 않고, 점 무늬 캔버스·프레임 이름표·현재 프레임의 선택 테두리 정도만 차용합니다.

### 프레임 배치

```
  ┌──────────┐
  │ 첫 화면  │
  │  /       │
  └──────────┘
       │
  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
  │ 소개     │──│ 경력     │──│ 프로젝트 │──│ 기술     │──│ 학력·자격│
  │ /about   │  │ /career  │  │/projects │  │ /skills  │  │/education│
  └──────────┘  └──────────┘  └──────────┘  └──────────┘  └──────────┘
                                                               │
                                                          ┌──────────┐
                                                          │ 연락처   │
                                                          │ /contact │
                                                          └──────────┘
```

### 프레임별 라우트

| 프레임    | 경로         | title                      |
| --------- | ------------ | -------------------------- |
| 첫 화면   | `/`          | 김규리 · 프론트엔드 개발자 |
| 소개      | `/about`     | 소개 · 김규리              |
| 경력      | `/career`    | 경력 · 김규리              |
| 프로젝트  | `/projects`  | 프로젝트 · 김규리          |
| 기술      | `/skills`    | 기술 · 김규리              |
| 학력·자격 | `/education` | 학력·자격 · 김규리         |
| 연락처    | `/contact`   | 연락처 · 김규리            |

직접 접근하면 해당 프레임에서 시작합니다.

## 이동

이동 방식은 화면 폭이 아니라 **입력 방식**으로 결정합니다.

### 마우스·트랙패드 (pointer: fine) — 카메라 이동

사용자는 아래로만 스크롤합니다. 카메라가 프레임 사이를 이동하는 것은 스크롤 위치에 연동된 연출입니다.

- 첫 화면 → 소개: 아래로 이동
- 소개 → 경력 → 프로젝트 → 기술 → 학력·자격: 카메라가 오른쪽으로 (가로 스크롤을 흉내 내는 연출)
- 학력·자격 → 연락처: 아래로 이동
- 긴 프레임: 카메라가 아래로 따라 내려가고, 끝에 닿은 뒤 다음 스크롤에서 다음 프레임으로 전환

### 터치 (pointer: coarse) — 좌우 스와이프

프레임 안에서는 세로 스크롤, 프레임 사이는 좌우 스와이프로 이동합니다. 옆 프레임 가장자리(12px)와 간격(12px)이 보여서 넘길 수 있다는 힌트 역할을 합니다.

### 폴더블 기기

폴더블은 접힘·펼침 모두 터치(pointer: coarse)이므로 항상 스와이프 방식입니다. 접힘 ↔ 펼침으로 뷰포트가 바뀌어도 이동 방식이 전환되지 않습니다.

## 옆 프레임

현재 프레임 좌우로 이웃 프레임이 살짝 보이고, 누르면 해당 프레임으로 이동합니다. 긴 프레임을 따라 내려가면 옆 프레임은 위로 지나가고 빈 캔버스가 보이는 게 정상입니다.

## 프레임 끝 안내

상시 이동 버튼은 두지 않습니다. 프레임 끝에 닿았을 때만 하단에 "계속 스크롤하면 03 프로젝트 →" 같은 안내를 잠깐 표시합니다.

## 뒤로 가기 기록

- 스크롤로 프레임이 바뀌면: 주소만 교체 (`replaceState`, 기록 안 남김)
- 메뉴를 눌러 이동하면: 기록 추가 (`pushState`)

## 구현 원칙

### 스크롤은 진짜, 카메라 이동은 연출

실제 문서는 프레임 순서대로 이어지는 일반 페이지이고, 화면의 카메라 이동만 스크롤 위치에 연동된 효과로 처리합니다. 아래가 정상 동작해야 합니다:

- 키보드 탐색 (Tab, 화살표, 스페이스)
- 스크린리더 (프레임 순서대로 읽힘)
- 페이지 내 검색 (Ctrl+F)

### prefers-reduced-motion

카메라 이동 없이 일반 세로 페이지로 표시합니다.

### 뷰포트 변경 시 유지

접힘 ↔ 펼침, 가로 ↔ 세로 전환 시 현재 프레임과 스크롤 위치가 유지되어야 합니다.

## 이력서 데이터

첫 화면, 소개, 경력 타임라인, 기술·학력 프레임, Person JSON-LD, 인쇄 이력서, Phase 4 에이전트가 `content/resume/`의 데이터 하나를 같이 씁니다.

- 형식은 TS입니다 (`profile`, `intro`, `timeline`, `skills`, `education`·`certifications`). 타입은 `src/lib/resume/types.ts`에 있습니다.
- 형식이 틀리면 빌드가 실패합니다 (기간 `YYYY-MM`과 순서, id 중복, URL·이메일 형식, 기술의 `firstUsedIn`, 프로젝트 글의 `timelineId`).
- 아직 모르는 값은 지어내지 않고 `TODO`로 둡니다. `TODO`는 형식 검사를 건너뛰고 화면·JSON-LD·평문에서 빠집니다.
- 진행 중이면 `period.end`를 생략합니다.
- 성과 요약(`achievements`)은 회사 레인에만 씁니다 (타입으로 막음).
- 경력 항목과 프로젝트 글의 연결은 글 frontmatter의 `timelineId` 하나가 기준입니다. 한 항목에 여러 글이 연결될 수 있고, 초안 글은 프로덕션에서 링크 없이 표시됩니다.
- 기술 분류는 고정 목록입니다: 언어·프레임워크 / 스타일링 / 데이터·상태 / 테스트·품질 / 협업·도구.

## 경력 섹션: 두 갈래 타임라인

| 레인               | 시각      | 내용                   |
| ------------------ | --------- | ---------------------- |
| 회사 (주)          | 굵은 막대 | 성과 요약              |
| 사이드·개인 (보조) | 얇은 선   | 이름, 한 줄 설명, 링크 |

- 부트캠프 시기 작업은 옅게 표시합니다.
- 케이스 스터디가 있는 항목만 모달로 열립니다.
- 학력·자격은 타임라인에 넣지 않고 별도 프레임에 둡니다.
- 사이드 레인의 마지막 항목은 이 포트폴리오입니다.
- 넓은 프레임(안쪽 폭 768px 이상)에서는 두 레인이 나란히. 좁은 프레임에서는 한 레인으로 접히고 상단에 레인 라벨이 표시됩니다.

## 여백 메모

본문의 특정 텍스트에 연결된 짧은 메모로, "왜 그렇게 했는지"를 적습니다. 연결된 텍스트는 점선 밑줄 등으로 표시합니다.

- 넓은 프레임(컨테이너 832px 이상): 메모를 본문 오른쪽에 항상 표시합니다. 메모나 연결 텍스트에 hover/focus 시 서로 강조됩니다.
- 좁은 프레임(832px 미만): 메모는 숨김 상태이고, 연결 텍스트를 누르면 해당 문단 바로 아래에 펼쳐집니다.

## 프로젝트 글 구조

모든 프로젝트 글(케이스 스터디)은 같은 형식입니다. 깊이는 글 길이로 자연스럽게 차이가 납니다.

권장 구성 (빌드에서 검사하지 않음):

1. 소개
2. 역할·기술
3. 주요 성과
4. 문제와 해결 — **"처음 떠오른 방법 / 한 번 더 들여다본 뒤"** 이야기를 여기서 풉니다.
5. 회고 — **"아직 남은 것"**을 여기서 풉니다.

- 원문은 `content/projects/{slug}.mdx`입니다. frontmatter: `title`, `summary`, `period`(`{ start, end }`, 진행 중이면 `end` 생략, `YYYY-MM`), `tags`, `thumbnail`(`/projects/{slug}/` 아래), `timelineId`(경력 타임라인 항목 id), `draft`(선택, 기본값 `false`).
- **초안:** `draft: true`인 글은 개발 서버(`yarn dev`)에서만 보이고 글 상단에 "초안" 표시가 붙습니다. 프로덕션 빌드에서는 페이지, 프로젝트 목록, sitemap, AI 지식 추출 모두에서 빠집니다. 공개하려면 `draft`를 지우거나 `false`로 바꿉니다. 빌드할 때 `SHOW_DRAFTS=true`를 주면 초안을 포함하는데, Lighthouse CI 측정 전용이며 배포 빌드에서는 쓰지 않습니다.
- 여백 메모는 글 안에서도 `MarginNoteGroup`·`MarginNoteAnchor`·`MarginNote`로 씁니다. 비교 블록 컴포넌트는 글을 쓰다가 필요해지면 추가합니다.
