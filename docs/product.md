# Product

## 컨셉

작은 불편을 그냥 지나치지 않고, 화면의 디테일부터 그 뒤의 구조까지 한 번 더 들여다본다.

## 첫 화면 문구

아래 문구를 그대로 사용합니다.

> 김규리 · 프론트엔드 개발자
>
> 작은 불편을 그냥 지나치지 않습니다.
> 화면의 디테일부터 그 뒤의 구조까지, 한 번 더 들여다보고 만듭니다.

## 섹션 구성

순서대로 배치합니다.

1. 첫 화면
2. 소개
3. 경력
4. 프로젝트
5. 기술
6. 학력·자격
7. 연락처

## 경력 섹션: 두 갈래 타임라인

| 레인               | 시각      | 내용                   |
| ------------------ | --------- | ---------------------- |
| 회사 (주)          | 굵은 막대 | 성과 요약              |
| 사이드·개인 (보조) | 얇은 선   | 이름, 한 줄 설명, 링크 |

- 부트캠프 시기 작업은 옅게 표시합니다.
- 케이스 스터디가 있는 항목만 모달로 열립니다.
- 학력·자격은 타임라인에 넣지 않고 별도 섹션에 둡니다.
- 사이드 레인의 마지막 항목은 이 포트폴리오입니다.

## 여백 메모

본문 옆 여백에 "왜 그렇게 했는지"를 짧게 적습니다. 메모에 hover 또는 focus하면 본문의 해당 줄이 강조됩니다.

## 케이스 스터디 글 구조

1. 상황
2. 판단
3. 한 일
4. 달라진 것
5. 아직 남은 것

각 케이스 스터디에는 **"처음 떠오른 방법 / 한 번 더 들여다본 뒤"** 비교 블록을 포함합니다.

## 문체

- 담담하게 씁니다.
- "대폭", "유의미하게" 같은 평가성 표현을 쓰지 않습니다.
- 수치는 전후 비교로만 보여줍니다.

## 인쇄

사이트를 인쇄하면 A4 이력서 형태가 됩니다. 여백 메모와 인터랙션 요소는 인쇄에서 제외합니다.

## 공개 금지 정보

아래 정보는 사이트와 케이스 스터디에 포함하지 않습니다.

- 매출 절대값
- 티켓 번호
- 내부 도구명
- 내부 문서 링크
