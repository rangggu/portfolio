# Responsive

## 원칙

- 기기 이름이 아니라 너비, 화면 비율, 컨테이너 크기로 분기합니다.
- 페이지 레이아웃은 미디어 쿼리, 컴포넌트는 컨테이너 쿼리(`@container`)를 씁니다.
- 모바일 우선(`min-width`)으로 작성합니다.

### 쿼리 문법: 범위 문법만 사용

미디어 쿼리와 컨테이너 쿼리 모두 범위 문법을 씁니다.

```css
/* Good */
@media (width >= 768px) { ... }
@container (width < 768px) { ... }

/* Bad — 금지 */
@media (min-width: 768px) { ... }
@media (max-width: 767px) { ... }
```

`max-width: 767px` 같은 -1px 방식을 쓰지 않습니다. 브라우저 확대·축소나 폴더블 기기에서 뷰포트가 767.5px처럼 소수점으로 잡히면 `min-width: 768px`과 `max-width: 767px` 사이에 틈이 생겨 어느 조건에도 해당하지 않는 구간이 발생합니다. 범위 문법은 이 문제가 없습니다.

## 브레이크포인트

| 이름 | 조건              | 뷰포트 범위 |
| ---- | ----------------- | ----------- |
| 기본 | `width < 768px`   | 0–767px     |
| md   | `width >= 768px`  | 768px 이상  |
| lg   | `width >= 1024px` | 1024px 이상 |

md와 lg 두 개만 씁니다. 컴포넌트별 세밀한 분기는 컨테이너 쿼리로 처리합니다.

## 너비 외 분기

| 상황         | 쿼리                                                    |
| ------------ | ------------------------------------------------------- |
| 폰 가로 모드 | `@media (orientation: landscape) and (height <= 440px)` |
| 짧은 랩톱    | `@media (width >= 1024px) and (height <= 700px)`        |

- `height <= 440px`은 가장 큰 폰(iPhone 16 Pro Max, 440px)의 가로 높이 기준입니다. 이 이하면 확실히 폰 가로 모드입니다.
- `height <= 700px`은 1024px 이상 너비에서 브라우저 UI를 뺀 실제 뷰포트 높이가 짧은 경우(13" 맥북 기본 해상도 등)를 감지합니다.

## 유동 타이포그래피·간격

`clamp()`로 뷰포트 360px → 1280px 구간에서 선형 보간합니다. 값은 `tokens.css`에 정의합니다.

| 토큰                | clamp 값                                   | 모바일 → 최대 |
| ------------------- | ------------------------------------------ | ------------- |
| `--font-size-48-72` | `clamp(3rem, 2.41rem + 2.61vw, 4.5rem)`    | 48→72px       |
| `--font-size-36-56` | `clamp(2.25rem, 1.76rem + 2.17vw, 3.5rem)` | 36→56px       |
| `--font-size-28-40` | `clamp(1.75rem, 1.46rem + 1.3vw, 2.5rem)`  | 28→40px       |
| `--font-size-20-24` | `clamp(1.25rem, 1.15rem + 0.43vw, 1.5rem)` | 20→24px       |
| `--layout-gutter`   | `clamp(1.25rem, 0.76rem + 2.17vw, 2.5rem)` | 20→40px       |

계산 공식: `slope = (max - min) / (1280 - 360)`, `intercept = min - slope × 360`

## 기기 특성 대응

### viewport-fit과 safe area

`viewport-fit=cover`를 설정하고, 노치·Dynamic Island·하단 바를 침범하지 않도록 `env(safe-area-inset-*)`를 씁니다.

```css
.root {
  padding-left: max(var(--layout-gutter), env(safe-area-inset-left));
  padding-right: max(var(--layout-gutter), env(safe-area-inset-right));
  padding-bottom: env(safe-area-inset-bottom);
}
```

### 100vh 대신 dvh/svh

`100vh`는 모바일 브라우저에서 주소창을 포함한 높이를 반환합니다. 첫 화면 같은 풀스크린 영역에는 `100dvh`를, 최소 높이에는 `100svh`를 씁니다.

### 가로 모드

가로 모드에서 높이가 부족하면 첫 화면의 수직 간격을 줄이고, 스크롤이 가능하도록 합니다.

### 세션 중 뷰포트 변경 (폴더블)

접힘 ↔ 펼침, 가로 ↔ 세로처럼 세션 중에 뷰포트가 바뀌어도 아래가 유지되어야 합니다:

- 스크롤 위치
- 열린 모달 (`<dialog>`)
- 클라이언트 상태 (`useState`, 스토어)

CSS가 뷰포트에 반응하면 레이아웃은 자동으로 바뀝니다. JS로 `window.innerWidth`를 캐싱해두고 쓰는 패턴은 피합니다.

## 폴더블 전용 CSS

`viewport segments`와 `device-posture` API는 지원 브라우저에서만 점진적 향상으로 적용합니다. 기본 레이아웃은 이 API 없이 동작해야 합니다.

```css
/* 점진적 향상: 폴드 힌지 영역에 간격 추가 */
@media (horizontal-viewport-segments: 2) {
  .twoPane {
    gap: env(viewport-segment-left 1 0) - env(viewport-segment-right 0 0);
  }
}
```

## 캔버스 프레임 레이아웃

### 이동 방식 전환 기준

화면 폭이 아니라 **입력 방식**으로 결정합니다.

| 조건                       | 방식          | 설명                                                   |
| -------------------------- | ------------- | ------------------------------------------------------ |
| `@media (pointer: fine)`   | 카메라 이동   | 사용자는 아래로만 스크롤. 프레임 간 이동은 카메라 연출 |
| `@media (pointer: coarse)` | 좌우 스와이프 | 프레임 안 세로 스크롤, 프레임 사이 좌우 스와이프       |

폴더블 기기는 접힘·펼침 모두 `pointer: coarse`이므로 항상 스와이프 방식입니다. 접힘 ↔ 펼침으로 뷰포트가 바뀌어도 이동 방식이 전환되지 않습니다.

### 프레임 폭 계산

프레임 폭 = 뷰포트 - (노출 + 간격) × 2, 최대 `--layout-page-max`(1440px).

**pointer: fine (카메라 이동):**

- 노출: `--layout-frame-peek` = `clamp(2rem, 4vw, 4.5rem)` (32→72px, 1440px에서 약 58px)
- 간격: `--layout-frame-gap` = `clamp(1rem, 2.5vw, 2.5rem)` (16→40px, 1440px에서 36px)
- 프레임이 1440px에 닿은 뒤(약 1652px 이상)에는 남는 폭을 프레임 사이 간격이 받아 옆 프레임은 계속 노출 폭(최대 72px)만 보입니다. 간격 = max(`--layout-frame-gap`, (뷰포트 - 프레임 폭) / 2 - 노출) (`Canvas.module.css`의 `--frame-gap`). 큰 화면일수록 프레임 둘레의 빈 캔버스가 넓어집니다.

**pointer: coarse (스와이프):**

- `@media (pointer: coarse)`에서 `--layout-frame-peek`, `--layout-frame-gap`을 각각 12px로 재정의

### 프레임 높이

한 프레임(이름표 + 본체)이 한 화면을 채웁니다. 위쪽 플로팅 UI와 이름표 사이는 `--spacing-12`(화면 위 끝 → 플로팅과 같은 값), 이름표와 본체 사이는 `--spacing-4`, 본체와 아래쪽 플로팅 UI 사이는 `--spacing-48`입니다 (프레임 끝 안내 말풍선이 메뉴 바 위에서 테두리를 가리지 않고 들어가는 자리).

```
위쪽 플로팅 영역 (--layout-floating-top)
간격 12px
프레임 이름표 (+ 4px)
프레임 본체   ← 최소 높이 = 100svh - 위쪽 플로팅 - 12px - 이름표 - 4px - 48px - 아래쪽 플로팅
간격 48px (프레임 끝 안내 자리)
아래쪽 플로팅 영역 (--layout-floating-bottom)
```

- 터치 기기(스와이프 모드)는 프레임 높이가 화면 높이로 고정되고 넘치는 내용은 프레임 안에서 스크롤됩니다 (「터치 스와이프 구현」).
- 최소 높이는 `100svh`를 씁니다 (최소 높이에는 svh, 「100vh 대신 dvh/svh」 참고). 주소창이 접히고 펼쳐져도 프레임 높이가 흔들리지 않습니다.
- 첫 화면 프레임만 내용을 세로 가운데 정렬하고, 나머지 프레임은 위에서부터 시작합니다 (안쪽 위아래 여백 `--spacing-48`, 폰 가로 모드 `--spacing-24`).
- 플로팅 UI는 이 영역 안에 그려집니다. 위: 위 `--spacing-12`, 좌우 `--spacing-16` 안쪽 (왼쪽 위 「Myu의 포트폴리오」 상자, 오른쪽 위 테마 · 모드 전환(마우스 기기 캔버스에서만) · 더보기 상자). 아래: 아래 `--spacing-20`, 가운데 메뉴 바 (반투명 블러 캡슐, 넘치면 바 안에서 가로로 밀어서 보기). 높이는 `--layout-floating-bar-height`이고 safe-area를 더합니다 (`features/canvas`의 `FloatingTop`, `FrameMenu`).

### 구현 원칙

**스크롤은 진짜, 카메라 이동은 연출.** 실제 문서는 프레임 순서대로 이어지는 일반 페이지이고, 화면의 카메라 이동만 스크롤 위치에 연동된 효과로 처리합니다.

- `prefers-reduced-motion: reduce`에서도 같은 화면(마우스 기기는 카메라, 터치는 스와이프)입니다. 스크롤·스와이프로 사용자가 직접 움직이는 것은 그대로 두고, 이동·확대 연출만 바로 바꿉니다 (`features/canvas/_lib/motion.ts`)
- 인쇄 시 캔버스 대신 종이용 A4 이력서 (product.md 「인쇄」, `features/resume`). 인쇄물은 세로로 쌓을 때 flex 대신 블록 흐름을 씁니다 (세로 flex는 Chromium에서 쪽이 갈릴 때 넘어간 항목이 뒤 항목과 겹침). 컨테이너 좌우 여백은 0(`@page` 여백 사용)입니다
- 접힘 ↔ 펼침으로 뷰포트가 바뀌어도 현재 프레임과 스크롤 위치 유지

### 데스크톱 카메라 이동 구현

카메라 모드는 `(pointer: fine)`이고 화면(`@media screen`)일 때만 켭니다 (움직임 줄이기와 상관없음). 켜지면 `<html data-camera>`가 붙고(첫 페인트 전 인라인 스크립트), 그 밖(인쇄·JS 전)은 세로 페이지, 터치는 스와이프입니다 (`features/canvas`의 `CameraScript`, `CameraController`).

- 구조: `main`(문서 높이 = 카메라 경로 길이 + 한 화면) > `stage`(화면에 고정, 넘침 숨김) > `world`(프레임을 캔버스 지도대로 놓은 grid). DOM 순서는 프레임 순서 그대로입니다.
- 배치: 첫 화면 위, 소개~학력·자격 한 줄, 연락처는 학력·자격 아래. 열 폭 = 프레임 폭, 열 간격 = `--layout-frame-gap`이라 한 프레임을 가운데 두면 양옆으로 `--layout-frame-peek`만큼 이웃이 보입니다.
- 경로(`src/lib/canvas/cameraTrack.ts`): 프레임마다 (긴 프레임이면 `lead`: 맨 위 너머에서 들어서는 구간, `hold`와 같은 길이. 위로 올릴 때 더 올리는 자리) → `follow`(긴 프레임을 아래로 따라감, 프레임 높이 - 화면 높이) → `hold`(끝을 지나 더 당기는 구간, 화면 높이 × 0.3. 긴 프레임은 카메라가 끝 너머로 그만큼 더 내려가 아래 캔버스가 드러나고, 화면 높이 프레임은 멈춰 있음. 프레임 끝 안내 표시) → `move`(다음 프레임으로, 옆이면 가로 거리·아래면 세로 거리). 스크롤 1px = 카메라 1px입니다. 휠·키 입력은 `src/lib/canvas/frameStep.ts`가 처리합니다. 긴 프레임은 아래로 `hold` 끝까지, 위로 `lead` 처음까지 그대로 스크롤되고, 그걸 넘거나 48px 이하만 남기는 입력이면 `move`를 스크롤로 지나가지 않고 다음 프레임 맨 위·이전 프레임 끝으로 곧장 미끄러집니다. 넘어간 뒤 같은 휠 동작(입력 간격 160ms 이내)은 버립니다. 프레임 끝 안내는 화면에 다 들어오는 프레임은 늘, 긴 프레임은 끝까지 화면 높이 × 0.5 이하가 남았을 때부터 보입니다. `move` 구간은 스크롤바를 끌거나 페이지 내 검색처럼 스크롤 위치가 직접 바뀔 때만 지나갑니다.
- 연출은 `world`의 `transform`만 씁니다. 카메라 모드에서는 `scroll-behavior: smooth`를 끕니다.
- 크기 변경: 프레임·화면 크기가 바뀌면 경로를 다시 만들고, 보던 구간과 그 안 진행 비율로 돌아갑니다.
- 포커스·페이지 내 검색: 브라우저가 결과를 보이려고 `stage`를 스크롤하면 그 위치를 실제 스크롤 위치로 바꾸고 `stage`는 되돌립니다. 앞쪽 프레임으로도 스크롤할 수 있게 `world`를 사방으로 띄워 둡니다(`--camera-room`).
- 기록: 스크롤로 프레임이 바뀌면 `replaceState`와 문서 제목 교체, 메뉴·옆 프레임 클릭은 `pushState`, 뒤로·앞으로 가기는 주소의 프레임으로 이동합니다.
- 이동 연출: 바로 옆 프레임(`FRAME_IDS` 순서로 한 칸)은 스크롤 경로를 거치지 않고 카메라 좌표를 출발 → 도착으로 곧장 옮긴 뒤(rAF로 `world`의 transform, `src/lib/canvas/cameraTravel.ts`, `--motion-camera-min/max-duration`) 도착하면 스크롤 위치를 맞춥니다. 경로를 따라가면 프레임 끝 멈춤 구간에서 카메라가 서 있는 동안 선택 표시만 바뀌어 튀어 보이기 때문입니다. 미끄러지는 동안은 휠·스크롤 키를 막고(`preventDefault`), 메뉴 이동이 옮기는 제목 포커스에 끼어들지 않으며, 선택 표시는 숨겼다가 도착 후 나타냅니다(`<html data-camera-traveling>`). 먼 프레임은 `world`를 `--duration-fast`로 페이드한 뒤 바로 옮깁니다. 움직임 줄이기면 모두 바로 옮깁니다.

### 자유 모드 구현

`<html data-canvas-mode="free">`일 때(마우스 기기 카메라 모드 안에서만) `CameraController`가 읽기 카메라(`startCamera`) 대신 `startFreeCamera`를 켭니다. 저장값(`localStorage` `canvas-mode`)은 `CameraScript`가 첫 페인트 전에 붙이고, 모드를 바꿀 때 보던 위치(`CameraHandoff`)를 넘겨줍니다.

- 문서는 스크롤하지 않고(`main` 높이 = `100dvh`) 입력을 직접 받습니다: `wheel`(passive: false), Safari 핀치 `gesture*`, `stage`의 포인터 끌기, 키보드. 계산은 `src/lib/canvas/freeCamera.ts`(이동·마우스 위치 중심 확대·전체 보기·포커스 보이기)입니다.
- `world`는 `transform: translate3d() scale()`(`transform-origin: 0 0`)로 움직이고, 조작 중에만 `will-change`를 켭니다(멈추면 풀어 확대한 글자를 선명하게 다시 그림). 점 무늬는 `stage` 배경에 배율·위치 변수(`--free-dot-*`)로 그리고, 간격이 좁아지면 두 배씩 성기게 합니다.
- 화면 가운데 프레임이 현재 프레임입니다. 메뉴·뒤로 가기는 `frameCamera`(100%, 가로 가운데·맨 위)로 날아갑니다.
- 포커스·페이지 내 검색: 포커스된 요소는 `revealBox`로 플로팅 UI를 피해 보이게 옮기고, 브라우저가 `stage`를 스크롤하면 그만큼 카메라를 옮긴 뒤 `stage`를 되돌립니다. 단축키는 입력 요소에 포커스가 있으면 동작하지 않습니다.

### 터치 스와이프 구현

스와이프 모드는 `screen and (pointer: coarse)`입니다. 입력 방식만으로 정하므로 움직임 줄이기와 상관없이 켜지고, 접힘·펼침·회전으로는 바뀌지 않습니다. 속성 없이 CSS 미디어 쿼리만으로 배치가 바뀌어 JS 전에도 같은 화면입니다 (`features/canvas`의 `SwipeController`, `_lib/swipe.ts`).

- 구조: 카메라 모드와 같은 `main` > `stage` > `world`이고 `data-camera-*` 속성도 함께 씁니다. 문서는 스크롤하지 않고(`main` 높이 = `100dvh`), `stage`가 가로·세로 스냅 스크롤 영역(`scroll-snap-type: both mandatory`)입니다.
- 배치: 카메라와 같은 캔버스 지도 grid. 한 행 = 화면 높이(`100cqh`), 행 간격 = `--layout-frame-gap`. 프레임은 화면 높이를 채우고 넘치는 내용은 **프레임 안에서** 세로로 스크롤됩니다. 멈추는 자리는 프레임 가운데(`scroll-snap-align: center`, `scroll-snap-stop: always`)라 양옆으로 이웃 가장자리 12px과 간격 12px이 보입니다.
- 위아래 이동: 첫 화면 ↔ 소개, 학력·자격 ↔ 연락처만 프레임 안 스크롤 끝에서 `stage`로 이어집니다(scroll chaining). 첫 화면·연락처는 옆이 빈 캔버스라 `touch-action: pan-y`로 가로 밀기를 막고, 경력·프로젝트·기술은 위아래가 빈 캔버스라 `overscroll-behavior-y: contain`으로 세로가 이어지지 않게 합니다.
- 빈 캔버스 보정: 2D 스냅이 빈 캔버스에 멈추면(`scrollend`에서 화면 가운데가 프레임 밖) 가장 가까운 프레임으로 옮깁니다.
- 현재 프레임: `stage` 스크롤 위치에서 화면 가운데가 든 프레임. 기록 규칙은 카메라 모드와 같습니다 (스와이프 = `replaceState`, 메뉴·옆 프레임 탭 = `pushState`).
- 옮기는 방식: 옆 프레임 탭은 미끄러지듯(smooth), 메뉴·뒤로 가기는 짧은 페이드 후 바로. 움직임 줄이기면 둘 다 바로 옮깁니다.
- 프레임 끝 안내: 프레임 안을 끝까지 내리면 「옆으로 넘기면 03 프로젝트 →」, 다음 프레임이 아래면 「아래로 넘기면 06 연락처 ↓」.
- 크기 변경: 프레임마다 세로 위치 비율을 기억해 두었다가, 화면 크기가 바뀌면 비율과 현재 프레임 위치를 되돌립니다.
- 포커스·페이지 내 검색: 브라우저가 `stage`와 프레임을 스크롤해 보이게 하고 스냅이 그 프레임에 맞춥니다.
- 감수한 것: 문서가 스크롤하지 않으므로 iOS 주소창이 접히지 않고, 상태 바를 눌러 맨 위로 가기가 동작하지 않습니다.

## 프레임별 반응형

### 첫 화면 (컨테이너 쿼리)

프레임 안쪽 폭 기준. 전환 기준: **768px** (경력 타임라인과 같다).

| 컨테이너 조건                 | 레이아웃                                                            |
| ----------------------------- | ------------------------------------------------------------------- |
| `@container (width >= 768px)` | 왼쪽 이름·소개 + 오른쪽 연락처 블록(280px, 열 간격 64px), 아래 정렬 |
| `@container (width < 768px)`  | 한 열, 연락처 블록이 내용 아래                                      |

### 경력 타임라인 (컨테이너 쿼리)

프레임 안쪽 폭(프레임 폭 - gutter×2) 기준. 전환 기준: **768px**.

| 컨테이너 조건                 | 레이아웃                                                                                                 |
| ----------------------------- | -------------------------------------------------------------------------------------------------------- |
| `@container (width >= 768px)` | 연도 행마다 연도(80px) + 회사 레인(3fr) + 사이드 레인(2fr) 나란히. 회사 막대는 끝난 해의 행까지 이어진다 |
| `@container (width < 768px)`  | 한 열(연도 → 회사 → 사이드), 상단에 레인 라벨. 막대만 이어지는 회사 칸은 숨긴다                          |

연도 행은 목록(`ol`), 레인 칸은 레인 이름이 붙은 그룹이라 한 열로 접혀도 보조기기가 「연도 → 회사 → 사이드」 순서와 레인을 구분해 읽는다.

### 프로젝트 · 기술 · 학력·자격 (컨테이너 쿼리)

프레임 안쪽 폭 기준. 전환 기준: **768px** (경력 타임라인과 같다).

| 프레임    | `@container (width >= 768px)`                                           | `@container (width < 768px)`                       |
| --------- | ----------------------------------------------------------------------- | -------------------------------------------------- |
| 프로젝트  | 행마다 번호(56px) · 제목·요약 · 메타 · 화살표 한 줄, 행 최소 높이 120px | 번호 · 제목·요약 · 화살표, 메타는 요약 아래        |
| 기술      | 분류 묶음 4열 (분류가 5개라 마지막 묶음은 다음 줄)                      | 분류 묶음 한 열                                    |
| 학력·자격 | 학력 · 자격 두 열 (행: 날짜 열 + 이름)                                  | 학력 → 자격 한 열, 480px 미만이면 날짜를 이름 위로 |

연락처 프레임은 문장과 연락처 묶음을 가운데 한 열로 두고 프레임 세로 가운데에 놓아, 폭 전환 없이 글자만 줄바꿈된다.

### 여백 메모 (컨테이너 쿼리)

메모는 본문의 특정 텍스트에 연결됩니다. 연결된 텍스트는 점선 밑줄 등으로 표시합니다.

전환 기준: **컨테이너 832px** = `--layout-prose-min`(560) + gap(32) + `--layout-note-width`(240).

| 컨테이너 조건                 | 표시 방식                                               |
| ----------------------------- | ------------------------------------------------------- |
| `@container (width >= 832px)` | 본문 오른쪽에 항상 표시                                 |
| `@container (width < 832px)`  | 숨김. 연결 텍스트를 누르면 해당 문단 바로 아래에 펼쳐짐 |

**넓은 프레임 (832px 이상):**

- 메모 폭 240px 고정(`--layout-note-width`), 간격 32px
- 본문은 560~720px 사이에서 유동 (`--layout-prose-min` ~ `--layout-prose-max`)
- 메모나 연결 텍스트에 hover/focus 시 서로 강조: 메모 카드 테두리·말풍선 아이콘이 포인트색, 연결 텍스트에 포인트 옅은 배경, 그리고 본문 열 끝에서 메모 아이콘까지 연결선(본문과 메모 사이 간격 안에서만 꺾임). 평소에는 연결선 없음
- 본문이 최대 폭(720px)에 도달한 뒤 남는 공간은 바깥 여백. 본문+메모 묶음은 가운데 정렬

**좁은 프레임 (832px 미만):**

- 메모는 숨김. 연결 텍스트를 누르면 해당 문단 바로 아래에 인라인 블록으로 펼쳐짐 (팝오버 아님)
- 좁은 프레임에서는 연결 텍스트 표시를 더 분명하게 (밑줄 두께, 색상 강조)
- 연결 텍스트는 `<button>`으로 구현하고 `aria-expanded`, `aria-controls`로 상태 전달
- 문장 속 인라인 텍스트라 44px 터치 영역 규칙의 예외이지만, 줄 간격(`--line-height-relaxed: 1.75`)으로 오터치를 방지

**구현 (`components/ui/MarginNote`, MDX 글과 일반 컴포넌트에서 같은 모양으로 사용):**

```tsx
<MarginNoteGroup>
  <p>
    … <MarginNoteAnchor note="why">연결 텍스트</MarginNoteAnchor> …
  </p>
  <MarginNote id="why">메모 내용</MarginNote>
</MarginNoteGroup>
```

- `MarginNoteGroup`이 서버에서 자식을 본문과 메모로 나눠, 메모가 항상 문단 뒤(넓으면 오른쪽 열)에 오게 합니다. `id`는 그룹 안에서만 유일하면 됩니다.
- 넓음/좁음은 CSS 컨테이너 쿼리가 정하고, JS는 그 결과만 읽어 `aria-expanded`를 맞춥니다.
- 긴 글은 `Prose`로 감쌉니다. 넓은 프레임에서 메모가 없는 블록도 본문 열 폭에 맞춰 정렬됩니다.

## 입력 방식 분기

너비와 별개로 입력 방식에 따라 분기합니다.

### hover

```css
@media (hover: hover) {
  .card:hover { ... }
}
```

hover로만 볼 수 있는 정보를 두지 않습니다. hover로 보여주는 내용은 focus나 다른 방법으로도 접근 가능해야 합니다.

### 터치 영역

- 기본 최소 크기: **44×44px** (Apple HIG, WCAG 2.5.5)
- 보이는 크기가 작아도 패딩이나 가상 요소(`::before`, `::after`)로 터치 영역을 넓힙니다.
- 공간이 불가피하게 부족한 경우에도 **24×24px** 이상 + 인접 요소와 간격 확보 (WCAG 2.5.8)

```css
.iconButton {
  position: relative;
}

.iconButton::before {
  content: '';
  position: absolute;
  inset: -8px;
}
```

### 복합 입력

태블릿 + 마우스, 터치스크린 노트북처럼 너비와 입력 방식이 엇갈리는 조합을 고려합니다.

```css
@media (pointer: coarse) {
  .target {
    min-height: 44px;
    min-width: 44px;
  }
}
```

## 이미지

`next/image`의 `sizes` 값을 브레이크포인트와 맞춰서 모바일에서 불필요하게 큰 이미지를 받지 않도록 합니다.

```tsx
<Image
  src={src}
  alt={alt}
  sizes="(width >= 1024px) 720px, (width >= 768px) 80vw, 100vw"
  fill
/>
```

- `sizes`의 브레이크포인트는 이 문서의 브레이크포인트와 일치시킵니다.
- 프로젝트 카드 썸네일처럼 작게 쓰이는 이미지는 최대 크기를 명시합니다.

## 개발 도구

`src/components/dev/ViewportIndicator.tsx`는 개발 모드에서만 화면 좌하단에 현재 뷰포트 너비×높이, 비율, 브레이크포인트 이름을 표시합니다. 프로덕션 빌드에는 포함되지 않습니다.
